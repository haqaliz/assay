# Implementation plan — `sandbox-core` (A2)

Date: 2026-10-23. Source: `docs/planning/sandbox-jail/prd.md` §4, §9 and
`docs/planning/sandbox-jail/sandbox-core/spec.md`. Strict TDD: each phase's tests are written and
seen failing before the implementation.

> Aspect note: the PRD proposed four aspects (`jail-config`, `seatbelt-launch`, `limits-teardown`,
> `denial-fixtures`). They share one package and one seam, and every one of them needs the same
> greenfield scaffold — so they are planned as phases here rather than duplicating setup in four
> specs.

## 1. Project setup checklist

- `pyproject.toml` — non-package uv project (`requires-python = ">=3.12"`, no build backend),
  dev group `pytest`, `[tool.pytest.ini_options] pythonpath = ["src"]`, `testpaths = ["tests"]`.
- `src/assay/__init__.py`, `src/assay/sandbox/__init__.py` (public exports).
- `tests/conftest.py` — `run_root` fixture (temp dir, per-run random suffix), `darwin_only` marker.
- No runtime dependencies. Stdlib only: `dataclasses`, `hashlib`, `json`, `ipaddress` (not
  needed after the CIDR drop), `resource`, `shutil`, `signal`, `subprocess`, `os`, `time`, `uuid`.

## 2. Implementation phases

### Phase 1 — Config and records (pure data, no process)

Goal: validated `JailConfig`, deterministic `config_hash`, the record types.
Files: `src/assay/sandbox/config.py`, `src/assay/sandbox/records.py`, `tests/test_config.py`,
`tests/test_records.py`.
Tests first: bad `run_root` (relative/nonexistent/not-a-dir) raises `ValueError`; bad `NetRule`
host/port raises; zero or negative limits raise; hash is stable across key order and differs when
any operational field changes; `run_root`/`keep` are excluded from the hash.
Validation: `uv run pytest tests/test_config.py tests/test_records.py`.
Commit: `feat(sandbox): validated jail config and run records`

### Phase 2 — Denial classification

Goal: `classify_failure(stderr, limit_exceeded)` → tuple of `DenialRecord`.
Files: `src/assay/sandbox/denials.py`, `tests/test_denials.py`.
Rules: `assay-denial: <kind> <detail>` marker wins; otherwise `Operation not permitted` /
`Permission denied` lines are classified by keyword (`network`/`connect`/`socket` → network,
`read`/`open` → file-read, `write`/`>` → file-write, else unknown); dedupe by (kind, detail);
detail truncated to 200 chars; `limit_exceeded` always yields a `LIMIT` record first.
Tests first: table-driven, one case per kind + marker + dedupe + truncation.
Validation: `uv run pytest tests/test_denials.py`.
Commit: `feat(sandbox): classify sandbox denials`

### Phase 3 — Backend selection + Seatbelt profile generation

Goal: fail-closed selection; profile text derived from config.
Files: `src/assay/sandbox/base.py`, `src/assay/sandbox/seatbelt.py` (profile part only),
`tests/test_selection.py`, `tests/test_seatbelt_profile.py`.
Tests first: `select_sandbox(platform="linux")` raises `SandboxUnavailable`; missing
`sandbox-exec` raises; darwin + present returns `SeatbeltSandbox`; profile contains
`(deny default)`, the host-data deny list, run-root read/write, no `network` substring when the
allowlist is empty, and exactly one `(allow network-outbound (remote tcp "<host>:<port>"))` per
rule; a port is rendered as an int, never interpolated.
Validation: `uv run pytest tests/test_selection.py tests/test_seatbelt_profile.py`.
Commit: `feat(sandbox): seatbelt profile builder and fail-closed selection`

### Phase 4 — Launch, limits, teardown

Goal: the real `SeatbeltSandbox.run()`.
Files: `src/assay/sandbox/seatbelt.py` (launch part), `tests/test_launch.py`.
Details: `.assay/` output dir inside the run root; `Popen` with `cwd=run_root`, `env` = PATH +
config env, `start_new_session=True`, `preexec_fn` setting `RLIMIT_CPU`/`RLIMIT_FSIZE`/
`RLIMIT_NPROC`; `communicate(timeout=wall_seconds)`; on timeout `killpg(SIGKILL)` and
`limit_exceeded="wall_seconds"`; signal mapping (`SIGXCPU`→`cpu_seconds`, `SIGXFSZ`→`file_bytes`);
read back ≤ 1 MB each stream; finally always `killpg` (guarded by a session-leader check) and
remove the run root unless `keep`; `SandboxFailed` (not a traceback) when the profile is rejected
(exit 71/134 before the child runs).
Tests first, all against a fixture probe script: exit code passthrough; env scrub
(`ASSAY_TEST_SECRET` absent); cwd is the run root; output cap + `truncated`; wall-clock kill with
`limit_exceeded`; CPU-bomb killed by `SIGXCPU`; no orphan after teardown; `keep=True` preserves.
Validation: `uv run pytest tests/test_launch.py`.
Commit: `feat(sandbox): launch, limits and teardown`

### Phase 5 — Confinement acceptance suite (the M0.2 gate)

Goal: prove the jail on this machine.
Files: `tests/test_jail_escape.py`, `tests/fixtures/*.py`, `tests/test_limits.py`.
Tests first: PRD §9 tests 1, 2, 5, 9, 11 — network denied + classified, write outside denied /
inside allowed, `../../etc/passwd`, `/etc` write, `~/.ssh` read, symlink escape, allowlist
port-scoping; plus the limit test from Phase 4 run through the full jail.
Validation: `uv run pytest -m darwin`.
Commit: `test(sandbox): confinement acceptance suite (M0.2)`

## 4. Testing strategy

- Unit tests (phases 1–3) run everywhere, no confinement needed.
- Confinement tests (phases 4–5) are marked `darwin` and skipped elsewhere; they use a local
  loopback listener and documentation-range addresses only. No external host is contacted.
- Nothing depends on wall-clock ordering: the timeout test uses a 1.5 s cap against a `sleep 30`.
- Determinism: `duration_s` is asserted as a range, never an exact value; hashes are asserted on
  canonicalized inputs.

## 5. Environment & determinism

`uv sync --dev`, then `uv run pytest`. Python 3.12+ provisioned by uv (system 3.9.6 is not used).
No env vars required; no `.env`; BYOK keys are out of scope for A2.

## 6. Edge cases & error handling

| Condition | Result |
|---|---|
| Non-Darwin, or `sandbox-exec` missing | `SandboxUnavailable` → A5 `UNVERIFIED/SANDBOX_UNAVAILABLE`; nothing runs |
| Profile rejected by `sandbox-exec` (exit 71) or child SIGABRT before exec (134) | `SandboxFailed` → `UNVERIFIED/SANDBOX_FAILED` |
| Wall-clock breach | killed; `limit_exceeded="wall_seconds"`, `signal=SIGKILL` |
| `RLIMIT_CPU` breach | `signal=SIGXCPU`, `limit_exceeded="cpu_seconds"` |
| `RLIMIT_FSIZE` breach | `signal=SIGXFSZ`, `limit_exceeded="file_bytes"` |
| Output > 1 MB | truncated, `truncated=True` |
| Teardown fails | recorded on the record; never swallowed, never raises over a completed run |

## 7. Agent execution notes

- Human checkpoints: after Phase 3 (review the generated profile by eye — it is the security
  boundary) and after Phase 5 (the acceptance run).
- Iteration likely: Seatbelt profile details (which `allow` classes the child needs). If the
  child dies with 134/SIGABRT, that is a profile problem, not a product bug — widen read access,
  never narrow it inside host-data paths.
- Ask before: adding any dependency, touching `.claude/`, or changing the PRD's acceptance list.
