## 2. Implementation phases

### Phase 1 — Records

**Files:** `src/assay/verdict/records.py`, `src/assay/verdict/__init__.py`,
`tests/test_verdict_records.py`.

**API (exact):**
```python
class Verdict(StrEnum): CLEAN="clean"; FLAGGED="flagged"; MALICIOUS="malicious"; UNVERIFIED="unverified"
class FindingClass(StrEnum): UNDECLARED_FILE="undeclared-file"; UNDECLARED_NETWORK="undeclared-network"
                             SHELL="shell"; INSTRUCTIONS="instructions"
class Severity(StrEnum): LOW="low"; REVIEW="review"; HIGH="high"
    @property def rank(self) -> int            # LOW 0, REVIEW 1, HIGH 2
class UnverifiedCause(StrEnum): NO_TRIGGER="no-trigger"; NO_DECLARED_SCOPE="no-declared-scope"
                                AGENT_FAILED="agent-failed"; COST_CAPPED="cost-capped"
class Strictness(StrEnum): BASELINE="baseline"; STANDARD="standard"; STRICT="strict"
class VerdictError(ValueError): ...

@dataclass(frozen=True, slots=True)
class Finding:
    class_: FindingClass
    severity: Severity
    target: str
    reason: str
    outcome: EventOutcome
    review_required: bool = False

@dataclass(frozen=True, slots=True)
class Assessment:
    verdict: Verdict
    findings: tuple[Finding, ...]
    cause: UnverifiedCause | None
    blocked: bool
    strictness: Strictness
    skill_content_hash: str
    trace_hash: str
    @property def review_required(self) -> bool   # any finding requires review
```
**Validation:** `Verdict is UNVERIFIED` ⇔ `cause is not None`; `blocked` and `review_required` bools;
hashes 64 lowercase hex; findings are `Finding`; `target`/`reason` non-empty strings.
**Tests first:** the enum sets, the verdict/cause invariant, review_required aggregation.
**Commit:** `feat(verdict): assessment records and the verdict contract`

### Phase 2 — Strictness and the floor

**Files:** `src/assay/verdict/policy.py`, `tests/test_verdict_policy.py`.

**API:**
```python
FLOOR: Mapping[FindingClass, Severity]       # REVIEW for all four, read-only
class FloorViolation(VerdictError): ...
@dataclass(frozen=True, slots=True)
class StrictnessPolicy:
    level: Strictness = Strictness.STANDARD
    floors: Mapping[FindingClass, Severity] = field(default_factory=lambda: dict(FLOOR))
    def floor(self, class_: FindingClass) -> Severity
DEFAULT_POLICY = StrictnessPolicy()
```
**Rules:** floors must contain exactly the four classes; values must be `Severity`; `REVIEW <= value`;
`INSTRUCTIONS` must be exactly `REVIEW`. Any violation raises `FloorViolation`. Floors are frozen to a
plain dict in `__post_init__`.
**Tests first:** default; raising a class to HIGH allowed; LOW rejected; missing/unknown class
rejected; instructions above REVIEW rejected; bad level rejected.
**Commit:** `feat(verdict): strictness policy with an unlowerable floor`

### Phase 3 — Precedence: failure, no trigger, gaps, clean

**Files:** `src/assay/verdict/assess.py`, `tests/test_verdict_assess.py`.

**API:** `assess(skill: Skill, trace: Trace, *, policy: StrictnessPolicy = DEFAULT_POLICY) -> Assessment`.

**Order:** (a) `trace.cause` → `UNVERIFIED` (`COST_CAPPED` for `cost-capped`, else `AGENT_FAILED`);
(b) compute `diff(skill, trace)` (propagates `CaptureError`); (c) non-instruction events == 0 and no
findings → `NO_TRIGGER`; (d) no findings and any of files/network/tools `None` →
`NO_DECLARED_SCOPE`; (e) `CLEAN`.
**Blocked:** `MALICIOUS` always; else `BASELINE` any HIGH, `STANDARD` any finding, `STRICT` any
finding or `UNVERIFIED`.
**Tests first:** each precedence step, each blocked level, trace from another skill raises.
**Commit:** `feat(verdict): assess precedence and strictness blocking`

### Phase 4 — Findings from divergences

**Files:** `src/assay/verdict/assess.py`, `tests/test_verdict_findings.py`.

**Rules:** spec criteria 6–11.
```python
SHELL_PATTERNS = ("rm -rf /", "| sh", "| bash", "base64 -d", "nc -", "id_rsa", "/etc/passwd")
```
- `EXCEEDED` file read/write → `UNDECLARED_FILE` REVIEW.
- `EXCEEDED` file write, `PurePath(target).is_absolute()`, outcome `OK`/`DENIED` → HIGH.
- `EXCEEDED` network → `UNDECLARED_NETWORK` REVIEW.
- shell `UNDECLARED`/`EXCEEDED` → `SHELL` REVIEW; HIGH if any pattern is a case-insensitive
  substring and outcome `OK`/`DENIED`.
- `UNDECLARED` file/network → no finding.
- `FAILED` never HIGH.
- Apply `effective = max(base, policy.floor(class_))`; instructions excluded here.
- any HIGH → `MALICIOUS` (all HIGH findings `review_required`); else any finding → `FLAGGED`.
**Tests first:** every row, denied vs failed, declared Bash suppresses shell, floor raising.
**Commit:** `feat(verdict): findings and malicious patterns from captured behavior`

## 6. Edge cases

| Condition | Result |
|---|---|
| `trace.cause="cost-capped"` with dangerous events | `UNVERIFIED/COST_CAPPED`, no findings |
| Other `trace.cause` | `UNVERIFIED/AGENT_FAILED` |
| Only instruction events | `NO_TRIGGER`, unless a pattern matched → `FLAGGED` |
| All dimensions declared, one event, no divergence | `CLEAN` |
| Declared `tools` includes `Bash`, shell ran | no shell finding |
| Shell command matched pattern but outcome `FAILED` | `REVIEW`, not `HIGH` |
| Instruction pattern with no events | `FLAGGED`, never `MALICIOUS` |
| Policy raises `SHELL` floor to `HIGH` | a benign shell exceedance becomes `MALICIOUS` |
| Policy lowers any floor to `LOW` | `FloorViolation` at construction |
| Trace from another skill | `CaptureError` before assessment |

## 8. Deviations during implementation (2026-10-30)

An adversarial review found one product-defeating blocker and several gaps. All are fixed and
covered by failing tests first:

1. **A declared `Bash` disabled the dangerous-command detector.** `rm -rf /` under declared Bash
   returned `CLEAN`. Dangerous shell patterns and absolute writes are now scanned from captured
   events independently of declarations; a declared `Bash` only suppresses a *benign* shell finding.
2. **Denied attempts inside declared scope were `CLEAN`.** Any `DENIED` event is now at least a
   `REVIEW` finding with the denial text, even when the action was within scope.
3. **`TOOL` events counted as behavior**, so a hallucinated tool call could be `CLEAN`. Only
   file/network/shell events count; a tool-only run is `NO_TRIGGER`.
4. **Patterns were unanchored substrings** (`rm -rf /tmp`, `| shasum`, `id_rsa.pub` were
   `MALICIOUS`). They are now anchored regexes over NFKD-normalised, casefolded, whitespace-collapsed
   commands, with lookalike tests.
5. **The user task was scanned as if it were the skill.** Only `target == "system"` instruction
   excerpts plus the body/description are scanned.
6. **Raising a floor manufactured `MALICIOUS`.** Floors are fixed at `REVIEW`: lowering and raising
   both raise `FloorViolation`; strictness is changed with `level` only.
7. **Record invariants were bypassable** with string enums, a findings list, or `MALICIOUS` without
   a `HIGH`. Every field is type-checked, findings are copied to a tuple, and the verdict/finding
   invariants are enforced at construction.
8. **A4 crash:** a tool call with a missing `path`/`url` produced an empty target and crashed
   `capture`. It now records `invalid-path`/`invalid-url` as a failed event.

## 9. Dogfood calibration (2026-10-31)

The M0.3 dogfood (`~/Desktop/assay-dogfood-2026-10-31/`) ran all 10 Plumb skills against the local
model and found one false `MALICIOUS`: `plumb-report` writing its report to the Desktop. The rule is
now `HIGH` only for sensitive absolute locations or when a declared file scope was exceeded; a
Desktop write with no declared scope is `REVIEW`/`FLAGGED`. Budget stops (`step-limit`,
`action-limit`, `wall-limit`) now report `UNVERIFIED/BUDGET_LIMIT` instead of `AGENT_FAILED`.
