# Plan — `real-corpus` / `core` (private real-world control)

Source: `docs/planning/real-corpus/prd.md` + `core/spec.md`. Date: 2026-11-05.
Baseline: `master` @ `84667e5` (A5 calibration merged), 874 tests. No code/dependency change.

## Phase 1 — Run the eight skills and create the cases

**Files:** create `corpus/real/cases/<id>/` for the eight skills; create
`corpus/real/README.md`.

**Steps:**

1. For each skill (`plumb-begin`, `plumb-end-fast`, `plumb-end`, `plumb-next`, `plumb-worktrees`,
   `prd-generator`, `prd-interview`, `tech-plan`):
   - run the local check from the spec with a temporary `--out` and `--json`;
   - capture the exit code and the JSON; the trace path is `payload["trace"]`;
   - if no trace is produced, stop and report the skill and the error; do not fabricate a case;
   - copy the trace and the skill's `SKILL.md` into `corpus/real/cases/<skill>/`;
   - write `case.json` with `id` = directory name, `label:"clean"`, `labeler:"aliz"`,
     `labeled_at:"2026-11-05"`, a rationale from the skill's description/purpose, `source:"local-model"`,
     `strictness:"standard"`, `trace` = the copied filename, `expected_classes: []`.
2. Verify each case loads: `uv run assay corpus corpus/real/` and `--json`; save the exact reports.
3. If any case is `MALICIOUS`, stop and report it; do not relabel or delete. A false `MALICIOUS` on a
   benign own skill is an incident to review.
4. `corpus/real/README.md`: provenance (model, base URL, date, prices, caps, one run per skill), the
   eight cases, the verdict distribution/coverage, and the limits (own benign skills, one run, not
   an audit, not a benchmark, no publication, no bundles).

**Validation:** `uv run assay corpus corpus/real/`; the 20-case `corpus/` report unchanged.

**Commit:** `test(corpus): add the private real-world control set`

## Testing strategy

- The test loads the stored cases; no model call.
- `assay corpus corpus/real/` computes the report; the verdict distribution is recorded, not pinned.
- The main 20-case and A5 held-out tests stay unchanged.
- If a false `MALICIOUS` appears, the test fails; stop and review.

## Edge cases & error handling

| Case | Expected |
|---|---|
| Ollama unavailable | Stop and report; do not fabricate |
| A run produces no trace | Stop and report the skill/error |
| A run is `UNVERIFIED` | Store it; the report counts the cause |
| A run is `FLAGGED` | Store it; clean review is reported |
| A run is `MALICIOUS` | Stop; false-positive incident; no relabel/delete |
| Trace/skill hash mismatch | Re-copy the exact files; the loader refuses a mismatch |
| Main corpus changes | Investigate; the real set must not touch it |
| Local model timeout | The trace is still stored if the run produced one; otherwise stop |
