# Plan — `a5-calibration` / `core` (A5 held-out shell calibration)

Source: `docs/planning/a5-calibration/prd.md` + `core/spec.md`. Date: 2026-11-05.
Baseline: `master` @ `533436d` (MCP design merged), 863 tests. No new dependency.

## Phase 1 — Held-out cases and the baseline

**Files:** create `corpus/heldout/cases/<id>/` for the eight cases; create
`corpus/heldout/README.md`.

**Steps:**

1. Write each `SKILL.md` with `name`, `description`, `allowed-tools` (`Read` for malicious, `Bash`
   for clean), `metadata.assay.files: []`, `network: []`.
2. Build the traces with a one-off Python snippet: `Trace(skill_name=..., skill_content_hash=parse_skill(...).content_hash,
   task_sha256=sha256(task), cause=None, input_tokens=0, output_tokens=0, cost_usd=0.0,
   events=(Event(kind=SHELL, outcome=OK, target=<command>, content_sha256=sha256(""),
   content_bytes=0, excerpt=""),), sandbox_config_hashes=())`; save with `TraceStore(case_dir).save`.
3. Write `case.json` for each: `schema:1`, `id` = dir, `label`, `labeler:"aliz"`,
   `labeled_at:"2026-11-05"`, `rationale` (behavior, not verdict), `source:"synthetic"`,
   `strictness:"standard"`, `trace` = filename, `expected_classes` (`["shell"]` / `[]`).
4. Run `uv run assay corpus corpus/heldout/` **before touching `assess.py`** and save the exact
   output (human and `--json`) for the PR/README. Expected: 4 FLAGGED malicious, 4 CLEAN clean,
   precision null (0/0), recall 0.00 (0/4), detection 1.00 (4/4), false-MALICIOUS 0/4, coverage 1.00.
5. `corpus/heldout/README.md`: the split, the eight cases, the labels, the baseline/after, and that
   this is a calibration control (do not tune on it again).

**Validation:** `uv run pytest tests/test_corpus_repo.py` (main corpus unchanged) and
`uv run assay corpus corpus/heldout/` (baseline).

**Commit:** `test(corpus): add the held-out shell calibration set`

## Testing strategy

- Unit: pattern table (malicious/clean commands), `HIGH`/`review_required`.
- Integration: `assay corpus corpus/heldout/` before/after; the main 20-case metrics pinned.
- Regression: the existing A5 tests; no contract/floor change.
- Commands: baseline before the edit, after; full suite before commits.

## Edge cases & error handling

| Case | Expected |
|---|---|
| `dd of=/dev/null` / `of=/dev/zero` | no HIGH (guard) |
| `dd of=/dev/disk0` | HIGH |
| `socat EXEC:./server` | no HIGH (guard) |
| `socat EXEC:/bin/sh` | HIGH |
| `python3 -c "print('ok')"` | no HIGH |
| `python3 -c '... pty.spawn(...)'` | HIGH |
| `/dev/tcp/` in a command | HIGH |
| `chmod +x && ./script` | no HIGH (guard) |
| Main corpus | metrics unchanged; test pins |
| Held-out set | 4/4 malicious, 4/4 clean after |
| Contract/floor | untouched |

## Agent notes

- Measure the baseline **before** editing `SHELL_PATTERNS`; otherwise the before/after is lost.
- Do not tune the 20-case development corpus; it is the reported benchmark.
- Do not change instruction/network severity, the floor, or the verdict contract.
- The held-out set is synthetic and small; do not claim general precision.
- Commit per phase; full suite before each commit.

## Assumptions

- The eight commands are safe as synthetic strings (never executed).
- The main corpus has none of the four commands; the new patterns do not match it.
- The held-out set is a calibration control; a future change needs a new held-out set.
