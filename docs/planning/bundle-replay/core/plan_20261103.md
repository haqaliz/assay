## Phase 2 — Bundle schema 2 and replay

**Goal:** the bundle carries its skill source; `replay` re-derives the assessment; `verify` checks
both.

**Files:** modify `src/assay/bundle/records.py`, `src/assay/bundle/build.py`,
`src/assay/bundle/__init__.py`; update `tests/test_bundle_records.py`, `tests/test_bundle_build.py`,
`tests/test_bundle_sign.py`; add replay cases (in these files or `tests/test_bundle_replay.py`).

**Data model:**

```python
BUNDLE_SCHEMA = 2

@dataclass(frozen=True, slots=True)
class SkillSource:
    content_hash: str     # "sha256:" + 64 lowercase hex
    source: str           # exact SKILL.md text, non-empty, <= MAX_SKILL_BYTES
    # __post_init__: formats, size, sha256(source.encode("utf-8")) == content_hash

@dataclass(frozen=True, slots=True)
class Bundle:
    skill: SkillSource
    hash_list: HashList
    trace: Trace
    assessment: Assessment
    signature: Signature
    schema: int = BUNDLE_SCHEMA
```

- `Bundle.__post_init__` adds `skill.content_hash == hash_list.skill == "sha256:" +
  trace.skill_content_hash == "sha256:" + assessment.skill_content_hash`; the existing trace/sandbox
  checks stay.
- `to_payload()` adds `"skill": {"content_hash": ..., "source": ...}` and `schema: 2`; the signature
  covers it (minus `signature`).
- `from_json` exact top-level keys `{schema, hash_list, skill, trace, assessment, signature}`; exact
  `skill` keys `{content_hash, source}`; schema must be 2; schema 1 →
  `BundleError("bundle-invalid: bundle schema 1 is not replayable; rebuild it")`; `SkillSource`
  validation errors are `bundle-invalid`; canonical check unchanged.
- `create_bundle(skill: Skill, source: str, trace, strictness, signer)`:
  - `sha256(source.encode("utf-8")).hexdigest() != skill.content_hash` → `BundleError("skill-mismatch: …")`;
  - `assess(...)` as today; `hash_list_for`; payload includes the `SkillSource`; sign; return.
- `build(skill, source, trace, strictness, private_key)` binds the real signer.
- `replay(bundle) -> Assessment`:
  - `parse_skill_text(bundle.skill.source, Path("SKILL.md"))`; `SkillParseError` → `BundleError("replay-mismatch: stored skill does not parse: …")`;
  - parsed hash vs `bundle.trace.skill_content_hash`; mismatch → `replay-mismatch`;
  - `assess(parsed, bundle.trace, policy=StrictnessPolicy(level=bundle.assessment.strictness))`;
    `CaptureError`/`VerdictError` → `replay-mismatch`;
  - exact equality with `bundle.assessment`; mismatch → `BundleError("replay-mismatch: …")`; return
    the derived assessment.
- `verify(bundle, public_key)`: `verify_bundle(...)` (signature) then `replay(bundle)`.
- `verify_bundle(bundle, verifier)` stays signature-only (the injectable seam for tests).
- Export `SkillSource`, `replay` from `assay.bundle`.

**Tests:**

- Update the `Bundle` helpers to use a real `SOURCE` text parsed with `parse_skill_text`; the trace's
  `skill_content_hash` is that skill's hash. The `Signature` dummy stays.
- Schema 2 payload exact keys/values; `Bundle.from_json(to_json()) == bundle`; canonical refusals;
  schema 1 refused; skill source hash/size/type validation; source-vs-trace hash mismatch.
- `create_bundle` signs the unsigned payload including the source; source mismatch → `skill-mismatch`;
  replay success; a bundle with a valid but different assessment (CLEAN where `assess` gives FLAGGED)
  → `replay-mismatch`; an unparseable embedded source → `replay-mismatch`.
- `test_bundle_sign` `build(...)` calls gain the source; a real signed bundle verifies and replays;
  a signed false assessment is caught (re-sign with the same key).
- A corpus should-have: load one `corpus/cases/...` case, `build(skill, case.path/"SKILL.md" text,
  trace, strictness, key)`, `verify(bundle, key.pub)` passes; skipif no `ssh-keygen`. This proves no
  corpus regeneration.

**Validation:** `uv run pytest tests/test_bundle_records.py tests/test_bundle_build.py
tests/test_bundle_sign.py` then the full suite.

**Commit:** `feat(bundle): embed the skill source and replay the verdict`

## Phase 3 — CLI

**Goal:** `assay verify` prints and enforces the replay; `assay bundle` embeds the source.

**Files:** modify `src/assay/cli/main.py`, `src/assay/cli/output.py`; update
`tests/test_cli_bundle.py`, `tests/test_cli_verify.py`; add
`tests/test_cli_verify_replay.py` if the signed-lie test is long.

**Behaviour:**

- `_bundle`: after `parse_skill(skill_path)`, read the exact source:
  `source = skill_path.read_bytes().decode("utf-8")` (bytes, not `read_text`, to preserve CRLF);
  `OSError`/`UnicodeError` → `skill-invalid`. Pass `source` to `build(...)`. The `--skill` hash check
  in `create_bundle` catches a file that changed between the parse and the read.
- `_verify`: `verify(record, public_key)` now replays; catch `(BundleError, SigningError)` and map
  `replay-mismatch` → `REPLAY_MISMATCH` via the existing envelope.
- `render_verify`: human adds `replay: verified` after `signature: verified`; JSON adds
  `"replay": true`. `render_bundle`/bundle JSON unchanged except the bundle file's schema 2 (the
  command's own report does not echo the payload).
- `check` unchanged.
- `assay bundle` file name/exit unchanged; the file grows.

**Tests:**

- `test_bundle_writes...` asserts schema 2, `hash_list`, and a `skill` object whose `content_hash`
  matches; the bundle verifies and replays.
- `test_verify_succeeds...` asserts `replay: verified` and `"replay": true`.
- `test_verify_refuses_a_signed_false_assessment`: build a valid bundle, replace the assessment with
  a valid but different one (e.g. `CLEAN` with no findings where the trace has a shell finding),
  re-sign the unsigned payload with the test private key, write canonical; `verify` exits 1 with
  `REPLAY_MISMATCH`, no traceback.
- `test_verify_refuses_a_schema_one_bundle`: copy a schema-1 payload (or set `schema:1`) and a dummy
  signature → `BUNDLE_INVALID`, named.
- Existing tamper tests update for schema 2 / the `skill` key; `check`/`bundle` exact bytes remain.

**Validation:** `uv run pytest tests/test_cli_bundle.py tests/test_cli_verify.py
tests/test_cli_verify_replay.py tests/test_cli_output.py tests/test_cli_refusals.py
tests/test_cli_run.py`, then the full suite.

## Testing strategy

- Unit: text ingest (same hash/fields, BOM/CRLF, size, encoding); `SkillSource` and schema 2;
  replay equality and mismatch; signed-lie.
- Integration: `check` → `bundle` → `verify` with a throwaway key; a corpus case bundles/replays;
  schema-1 refusal.
- Manual: `uv run assay bundle` a saved trace, `uv run assay verify`, then edit the assessment and
  re-sign with the test key to see `REPLAY_MISMATCH` (the test automates it).
- Commands: targeted per phase, `uv run pytest` before each commit.

## Environment & secrets

- No env vars or secrets. Tests generate throwaway ed25519 keys; no key is committed.
- The embedded source is parsed, never executed or written to disk.
- The bundle cap stays 64 MiB on verify; the source cap is `MAX_SKILL_BYTES`.

## Edge cases & error handling

| Case | Expected |
|---|---|
| Source hash ≠ trace/assessment/hash list | `hash-mismatch`, exit 1 |
| Source unparseable | `replay-mismatch` |
| Source over `MAX_SKILL_BYTES` | `bundle-invalid` / `skill-mismatch` |
| Assessment doesn't follow from skill+trace | `replay-mismatch`, exit 1 |
| Schema-1 bundle | `bundle-invalid: not replayable`, exit 1 |
| Non-canonical bundle / unknown key | `bundle-not-canonical` / `bundle-invalid` |
| Tampered signature | `signature-invalid` |
| Wrong public key | `signer-mismatch` |
| Corpus trace (schema 2) bundled | builds and replays; no regeneration |
| `check`/`bundle` output | unchanged (bundle file is schema 2) |

## Agent execution notes

- Do not change `Trace`, `assess`, the corpus, or `check`.
- `parse_skill_text` must hash `text.encode("utf-8")`; never use `Path.read_text` for the source
  (universal newlines would change CRLF bytes).
- The replay equality includes `blocked` and `strictness`; use the recorded strictness.
- Update every `build`/`create_bundle` call site (CLI and tests).
- Commit per phase; run `uv run pytest` before each commit.
- If a schema-1 bundle test is awkward, construct a schema-2 payload, set `schema` to 1, and
  re-canonicalize; the refusal is by name.

## Assumptions

- The parser is deterministic for a given source; a parser change that alters `Skill` fields is a
  replay-semantics change and needs a bundle schema bump.
- Schema-1 bundles are pre-0.1 artifacts; refusing them is acceptable and named.
- The embedded `SKILL.md` is the exact file the run used; the trace's signed hash binds it.
