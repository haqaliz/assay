## Phase 3 — Bundle records, build, and verify (no CLI, no crypto)

**Goal:** a canonical, self-contained bundle that cross-checks its own hash list, and the
`build`/`verify` orchestration behind an injectable signer.

**Prerequisites:** Phases 1 and 2.

**Files:** create `src/assay/bundle/__init__.py`, `src/assay/bundle/records.py`,
`src/assay/bundle/build.py`; tests `tests/test_bundle_records.py`,
`tests/test_bundle_build.py`.

**Data model (exact):**

```python
# bundle/records.py
NAMESPACE = "assay"
BUNDLE_SCHEMA = 1

class BundleError(ValueError): ...

@dataclass(frozen=True, slots=True)
class HashList:
    skill: str                 # "sha256:<64 hex>"
    trace: str                 # "<64 hex>" (Trace.hash is bare)
    sandbox: tuple[str, ...]   # each "sha256:<64 hex>", sorted unique

@dataclass(frozen=True, slots=True)
class Signature:
    signer: str                # "SHA256:<base64>"
    value: str                 # armored SSHSIG, header ... footer
    namespace: str = NAMESPACE

@dataclass(frozen=True, slots=True)
class Bundle:
    hash_list: HashList
    trace: Trace
    assessment: Assessment
    signature: Signature
    schema: int = BUNDLE_SCHEMA
    # properties/methods: unsigned_payload(), unsigned_json(), to_payload(), to_json(),
    # from_json(text)
```

**Rules:**

- `HashList.__post_init__`: validate formats and sorted-unique sandbox hashes.
- `Signature.__post_init__`: `namespace == "assay"`; signer matches
  `^SHA256:[A-Za-z0-9+/]+$`; value starts `-----BEGIN SSH SIGNATURE-----` and ends
  `-----END SSH SIGNATURE-----` (allow one trailing newline).
- `Bundle.__post_init__`: `schema == 1`; `hash_list.skill == "sha256:" +
  assessment.skill_content_hash == "sha256:" + trace.skill_content_hash`;
  `hash_list.trace == assessment.trace_hash == trace.hash`;
  `hash_list.sandbox == trace.sandbox_config_hashes`. Any mismatch is a `BundleError`
  prefixed with `hash-mismatch:`.
- `Bundle.to_payload()` is exactly the PRD payload; `unsigned_payload()` is the same
  without `signature`; both use `canonical()`.
- `Bundle.from_json(text)`:
  - JSON object, exact top-level keys `{schema, hash_list, trace, assessment, signature}`,
    exact `hash_list`/`signature` keys;
  - `Trace.from_json(canonical(payload["trace"]))`;
  - `Assessment.from_payload(payload["assessment"])`;
  - reject when `to_json() != text` with `BundleError("bundle-not-canonical: ...")`;
  - wrap `CaptureError`/`VerdictError` as `BundleError("bundle-invalid: ...")`.
- `build.py`:

```python
def hash_list_for(trace, assessment) -> HashList
def bundle_payload(hash_list, trace, assessment) -> dict
def create_bundle(skill, trace, strictness, signer) -> Bundle
    # assess(...); hash_list_for; signer(canonical(unsigned_payload).encode()) -> Signature
def verify_bundle(bundle, verifier) -> None
    # verifier(bundle.unsigned_json().encode(), bundle.signature)
```

`signer`/`verifier` are callables so Phase 3 tests need no `ssh-keygen`. Phase 4 supplies
the real ones and a convenience `build(skill, trace, strictness, key)` / `verify(bundle,
public_key)`.

## Phase 4 — `ssh-keygen` signing adapter

**Goal:** real signatures and offline verification, with named failures and no key leakage.

**Prerequisites:** Phase 3.

**Files:** create `src/assay/bundle/sign.py`; extend `src/assay/bundle/build.py` and
`src/assay/bundle/__init__.py`; tests `tests/test_bundle_sign.py`.

**API:**

```python
class SigningError(Exception): ...   # messages are "<cause>: <detail>"

def fingerprint(public_key: Path) -> str          # "SHA256:…"
def sign(payload: bytes, private_key: Path) -> Signature
def verify(payload: bytes, signature: Signature, public_key: Path) -> None
```

**Implementation rules:**

- `_ssh_keygen() -> str` resolves `shutil.which("ssh-keygen")` per call; missing →
  `SigningError("ssh-keygen-not-found: …")`.
- `fingerprint`: the file must be one line and start with one of `ssh-ed25519`, `ssh-rsa`,
  `ecdsa-sha2-`, `sk-ssh-ed25519@openssh.com`, `sk-ecdsa-`; run `ssh-keygen -lf <path>`;
  exactly one output line; return field 2. Unreadable/multiple lines → `public-key-invalid`.
- `sign`:
  1. `ssh-keygen -y -f <private_key>` → public key text (nonzero →
     `signing-key-unavailable: <first stderr line>`).
  2. `ssh-keygen -lf -` with the public key on stdin → fingerprint.
  3. `ssh-keygen -Y sign -f <private_key> -n assay -` with `payload` on stdin.
  4. Nonzero → `signing-failed: <first stderr line>`; `TimeoutExpired` →
     `signing-timed-out: use a dedicated unencrypted key`; output must start with the
     SSHSIG header, else `signing-failed: unexpected output`.
  - `subprocess.run(list argv, input=…, capture_output=True, timeout=15)`; no shell;
    never print the key path or contents from Assay.
- `verify`:
  1. `fingerprint(public_key)`; if it differs from `signature.signer` →
     `signer-mismatch: expected … got …`.
  2. Write `assay <pubkey line>` to `allowed_signers` and `signature.value` to `sig` inside
     a `TemporaryDirectory`.
  3. `ssh-keygen -Y verify -f <allowed_signers> -I assay -n assay -s <sig> -` with the
     payload on stdin. Nonzero → `signature-invalid: <first stderr line>`.
- Convenience in `build.py`:
  `build(skill, trace, strictness, private_key)` and `verify(bundle, public_key)` bind the
  real adapter.

**TDD steps (`tests/test_bundle_sign.py`, `pytest.mark.skipif(shutil.which("ssh-keygen")
is None, reason="ssh-keygen not installed")`):**

1. `test_sign_and_verify_round_trip` — throwaway ed25519 key; sign; verify; signer equals

2. `test_signature_is_deterministic` — two signs of the same payload are byte-identical.

## Phase 5 — CLI `bundle` and `verify`

**Goal:** the two commands, the failure envelopes, and the exit contract.

**Prerequisites:** Phase 4.

**Files:** modify `src/assay/cli/main.py`, `src/assay/cli/output.py`; tests
`tests/test_cli_bundle.py`, `tests/test_cli_verify.py`, `tests/test_cli_args.py`.

**Parser:**

```
assay bundle <trace.json> --skill <SKILL.md|dir> --key <private-key>
             [--strictness baseline|standard|strict] [--out DIR] [--json]
assay verify <bundle.json> --public-key <pub> [--json]
```

**Behaviour:**

- `main` dispatches on `args.command`; `check` keeps its current validation and output
  path untouched.
- `_bundle`:
  - trace not a file → `trace-unreadable`; `TraceStore(parent).load` failure
    (`CaptureError`/`TraceIntegrityError`) → `trace-invalid`;
  - skill dir → `SKILL.md`; `SkillParseError` → `skill-invalid`;
  - `build(...)`; `CaptureError` → `skill-mismatch`; `SigningError` → its own cause prefix;
  - output path `args.out or trace_path.parent`, `mkdir(parents=True, exist_ok=True)`,
    filename `<trace-stem>.bundle.json`, atomic write (temp file + `os.replace`); `OSError`
    → `bundle-write-failed`;
  - print the report, exit 0.
- `_verify`:
  - `stat().st_size > 64 * 1024 * 1024` → `bundle-too-large`;
  - read bytes, UTF-8 decode → `bundle-invalid`;
  - `Bundle.from_json` → its cause prefix (`bundle-not-canonical`, `hash-mismatch`,
    `bundle-invalid`);
  - `verify(bundle, public_key)` → `signer-mismatch`, `signature-invalid`,
    `public-key-invalid`, `ssh-keygen-not-found`;
  - print, exit 0.
- Failure envelope in `output.py`:
  - JSON: `{"schema":1,"bundle":<path>,"cause":<cause>,"detail":<detail>}`;
  - human: `bundle:`, `cause: <UPPER_UNDERSCORE>`, `detail:`, `exit: 1`.
- Success output:
  - human: the shared skill/verdict/strictness/findings summary, then
    `bundle:`, `signer:`, and for verify `signature: verified`; `exit: 0`;
  - JSON: `{"schema":1,"bundle":path,"skill":{"name","content_hash"},"assessment":{…},
    "sandbox":[…],"signer":…}` plus `"verified":true` for verify.
- Exit codes: `0` success, `1` named failure, `2` usage/argparse, `130` Ctrl-C.
- Never print key material or the private-key path; never include the key path in JSON.

## Testing strategy

- **Unit:** Phase 1 trace records/capture; Phase 2 canonical + payload round trips; Phase 3
  bundle records/build with a fake signer/verifier; Phase 4 real `ssh-keygen` round trip,
  tamper, wrong key, missing binary; Phase 5 CLI parser, pipeline, envelopes, exit codes.
- **Integration:** `check` (fakes) → trace → `bundle` → `verify` (real throwaway key) in
  `tests/test_cli_verify.py`; the same flow with a tampered verdict/trace/key.
- **Manual (not CI):** with Ollama `qwen3-coder:30b`, run `assay check` on a Plumb skill,
  `assay bundle` the saved trace, `assay verify` with the public key, then edit a byte and
  watch it fail. This is the Phase 2 proof; it spends no API money.
- **Commands:** targeted files per phase, `uv run pytest` before every commit,
  `uv run assay --help` after Phase 5.

## Environment & secrets

- No env vars are required. `ASSAY_*` model settings are irrelevant to these commands.
- The private key is never copied, printed, or embedded. Use a dedicated passphrase-less
  key for the manual run; a passphrase prompt is bounded by a 15 s timeout and reported as
  `signing-timed-out`.
- Tests generate keys under `tmp_path`; no fixture key is committed.

## Edge cases & error handling

| Case | Expected |
|---|---|
| Trace with no executed action (`sandbox_config_hashes=()`) | Bundles; verify passes |
| `UNVERIFIED`/`BUDGET_LIMIT` trace | Bundles; verify passes; verdict preserved |
| Trace filename ≠ content hash | `trace-invalid` (from `TraceStore.load`) |
| Trace v1 | `trace-invalid` naming the schema |
| Skill changed since the run | `skill-mismatch`, no bundle written |
| Missing/unreadable private key | `signing-key-unavailable`, exit 1, no traceback |
| Passphrase prompt | `signing-timed-out`, exit 1 |
| `ssh-keygen` absent | `ssh-keygen-not-found`, exit 1; test skipped |
| Bundle > 64 MiB | `bundle-too-large` |
| Non-UTF-8 / malformed JSON | `bundle-invalid` |
| Pretty-printed / extra keys | `bundle-not-canonical` |
| Edited embedded trace/assessment/hash list | `hash-mismatch` |
| Signature replaced | `signature-invalid` |
| Wrong public key | `signer-mismatch` |
| `--out` is a file | `bundle-write-failed` |
| Ctrl-C | exit 130, no traceback |
