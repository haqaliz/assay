## 2. Implementation phases

### Phase 1 — Parser, script entry, validation

**Files:** `pyproject.toml`, `src/assay/cli/__init__.py`, `src/assay/cli/main.py`,
`tests/test_cli_args.py`.

**API:** `main(argv: Sequence[str] | None = None, *, model: Model | None = None,
sandbox: Sandbox | None = None) -> int`.
**Parser:** `prog="assay"`, required subcommand `check`, one positional `skill`; options per spec §2.
Missing model/price/cap after env fallback → one line on stderr, return 2. Invalid numbers →
one line, return 2. `--help` and unknown commands behave as argparse (SystemExit).
**Tests first:** help, unknown command, each missing setting, bad values, defaults.
**Commit:** `feat(cli): assay check parser and entry point`

### Phase 2 — Refusals, envelopes, no traceback

**Files:** `src/assay/cli/main.py`, `src/assay/cli/output.py`, `tests/test_cli_refusals.py`.

**API:** `render_human(skill, assessment, trace_path, trace) -> str`;
`render_json(...) -> str`; `refusal(kind: str, detail: str, path: Path, as_json: bool) -> str`.
**Rules:** parse refusal → `WONT_PARSE`; sandbox unavailable → `SANDBOX_UNAVAILABLE`; exit 1; no
trace. Unexpected exception at top level → `error: <Type>: <message>`, exit 2; KeyboardInterrupt 130.
**Tests first:** both envelopes (human + JSON, canonical), exit codes, no traceback, key absent from
output.
**Commit:** `feat(cli): named refusal envelopes without tracebacks`

### Phase 3 — Orchestration

## 4. Testing strategy

- Argparse behaviour through `main` with `pytest.raises(SystemExit)` where argparse owns the exit.
- Injected `FakeModel` (scripted replies) and `FakeSandbox` (canned `RunRecord`) mirroring the agent
  and capture test style.
- A real `SKILL.md` written to `tmp_path` for each run; no fixtures outside the repo.
- JSON stability by running `main` twice and comparing stdout bytes.
- One `subprocess` smoke test for the installed console script (`uv run assay check --help`).

## 5. Environment & secrets

Tests never read a real key: the model is injected. The manual run needs `ANTHROPIC_API_KEY`,
`--model`, both prices and `--max-cost`.

## 6. Edge cases

| Condition | Result |
|---|---|
| Missing skill path | argparse usage, exit 2 |
| Skill is a directory or malformed | `WONT_PARSE`, exit 1 |
| No API key and no injected model | one-line error, exit 2 |
| Sandbox unavailable | `UNVERIFIED/SANDBOX_UNAVAILABLE`, exit 1 |
| Cost cap hit before the first call | trace saved, `UNVERIFIED/COST_CAPPED`, exit 1 |
| Run root cleanup fails | ignored; the report still prints |
| `--out` is a symlink | `CaptureError` → one-line error, exit 2 |
| Unexpected exception | `error: Type: message`, exit 2 |
| Ctrl-C | exit 130, no traceback |

## 7. Agent execution notes

- Human checkpoint after Phase 3: run `main` by hand against a Plumb skill with the fake model.
- Do not add detection logic, config files or a user-facing fake mode.
- Do not print the API key or include it in any payload.
- Keep the JSON field set exactly as the spec; adding a field later requires a `schema` bump.

## 8. Deviations during implementation (2026-10-31)

An adversarial review found two blockers; both are fixed with failing tests first:

1. **The API key could be echoed** by an invalid-header `ValueError` when the key contained control
   characters. `AnthropicModel` now refuses such a key without printing it, and a transport
   `ValueError` becomes a generic `ModelFailed("transport failed: invalid request")`.
2. **A jail that failed to start could produce `CLEAN`/exit 0.** `SandboxFailed` is no longer turned
   into an ordinary failed tool result: it aborts the run, `drive` maps it to
   `SANDBOX_UNAVAILABLE`, and the CLI prints `UNVERIFIED` and exits 1.

Also fixed: findings captured before a cost/agent stop are preserved instead of discarded; the
trace destination is validated before any model call; the model and cap are printed to stderr before
the run; the human report sanitises control characters in skill names, targets and reasons (and
prints an explicit `exit:` line); refusal details are collapsed to one line and paths are
surrogate-safe; `--keep-run-root` prints the root even when the run fails; and the key-leak tests
now exercise a real `AnthropicModel` with a fake transport instead of an injected fake model.
