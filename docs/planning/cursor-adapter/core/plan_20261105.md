- Regression: Claude/OpenClaw bundle bytes and reports; corpus.

## Environment & secrets

- No env vars/secrets; tests use inline `.mdc` text and the existing throwaway key pattern.
- The bundle format hint is signed data; no new trust input.

## Edge cases & error handling

| Case | Expected |
|---|---|
| `alwaysApply: true` + globs | `files=("*",)`; globs ignored |
| `globs` string with commas | trimmed tuple |
| `globs` empty entry / wrong type | `INVALID_SCOPE` |
| only `description` | `files=None`; bundle stores the format |
| no frontmatter | named frontmatter refusal |
| `.md` in `.cursor/rules` | parsed as `SKILL.md` → missing name refusal; out of scope |
| `.cursorrules` / `AGENTS.md` | out of scope |
| write inside/outside globs | no finding / `FLAGGED` |
| no findings | `UNVERIFIED/NO_DECLARED_SCOPE` |
| Claude/OpenClaw bundle | no `format` key; bytes unchanged |
| old bundle without `format` | loads as before |
| invalid `format` in a bundle | `bundle-invalid` |

## Agent notes

- Do not change A5, trace schema, corpus, or existing bundle bytes for Claude/OpenClaw.
- `parse_skill` is the public dispatcher; keep `ClaudeSkillParser`/`parse_skill_text` behavior.
- The Cursor parser must reuse the existing frontmatter/read helpers; no second YAML path.
- The format hint is omitted for `CLAUDE_CODE`/`OPENCLAW`; do not emit it always.
- Commit per phase; full suite before each commit.

## Assumptions

- Cursor project rules are `.mdc` files with YAML frontmatter; globs are comma-separated or a list.
- `alwaysApply: true` means all files, regardless of globs/description.
- Tools/network are not declared by the format; a no-finding run is `UNVERIFIED`, not a pass.
