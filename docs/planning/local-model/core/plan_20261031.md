## 2. Phases

### Phase 1 — Adapter request/response

**Files:** `src/assay/agent/openai_compat.py`, `tests/test_agent_openai.py`.
**Tests first:** request URL/body shape, system/user/assistant/tool mapping, tool schema, response
text/tool calls/usage, keyless loopback, remote requires a key, control-character key refusal,
invalid tool arguments, truncation, transport errors.
**Commit:** `feat(agent): OpenAI-compatible model adapter`

### Phase 2 — Hardening

**Files:** `src/assay/agent/transport.py`, both adapters, tests.
**Rules:** disable environment proxies; refuse redirects; cap the response body; redact the key
from any error detail; require https for non-local base URLs; reject userinfo/query/fragment/bad
ports; ignore an ambient key for loopback; strict integer usage; accept text content blocks and
mapping tool arguments; refuse an empty reply.
**Tests first:** each rule above.
**Commit:** `fix(agent): harden the HTTP boundary for model calls`

### Phase 3 — CLI provider selection

**Files:** `src/assay/cli/main.py`, `tests/test_cli_run.py`.
**Rules:** `--provider {anthropic,openai-compatible}`, `--base-url`, `--api-key`; `--base-url` and
`--api-key` rejected for anthropic; base URL required for the new provider; the banner names the
provider and base URL but never the key; a skill directory resolves to `SKILL.md`.
**Tests first:** validation, construction, banner, directory.
**Commit:** `feat(cli): select the model provider and accept a skill directory`

### Phase 4 — Real run, docs

**Files:** docs only.
**Rules:** run the CLI against the real Plumb skill and Ollama; record the gate result honestly (local
model, not Claude); document both providers and the key rules; sync status and test counts.
**Commit:** `docs(local-model): document the local provider and the gate run`

## 4. Testing strategy

Injected transport, no sockets in the suite; one manual loopback run against Ollama after the suite
is green. The first real run produced the Phase 0 gate observation (see the PRD).

## 5. Environment & secrets

Local: no key. Remote: `ASSAY_API_KEY`, https only. The suite never reads a real key.

## 6. Edge cases

Covered in `core/spec.md`; the transport, usage and base-URL rules are the ones that bit in review.

## 7. Agent execution notes

- The Ollama run is manual; do not add it to CI.
- Do not add streaming, retries or a provider registry.
- Never print a base URL containing credentials; reject userinfo instead.

## 8. Deviations (2026-10-31)

An adversarial review found a proxy/redirect key-leak class and several parsing gaps. Fixed before
merge: environment proxies disabled, redirects refused, error bodies redacted, https required for
non-local URLs, ambient keys ignored for loopback, strict integer usage, response size cap,
overflow/recursion mapped to `ModelFailed`, content blocks and mapping arguments accepted, empty
replies refused, and `--api-key`/`--base-url` rejected for Anthropic. The skill-directory
convenience was added during the manual gate run and is documented in the PRD.
