   - sorted unique signals; no I/O.

## Testing strategy

- Unit: signal/priority table; no-verdict record; case-insensitivity; sorted unique signals.
- CLI: human/JSON exact, key set without verdict, parse refusal, exits, no writes.
- Regression: existing CLI/corpus/bundle tests unchanged.
- No model/sandbox/network.

## Edge cases & error handling

| Case | Expected |
|---|---|
| High-signal text | `HIGH`, labels sorted |
| Medium only | `MEDIUM` |
| Benign | `LOW`, `signals: none` |
| Both high and medium | `HIGH`, all labels |
| Case variants | matched (IGNORECASE) |
| Directory path | append `SKILL.md` |
| `.mdc` path | parse via the Cursor adapter; triage the body |
| Parse failure | triage envelope, exit 1, no traceback |
| Missing arg | argparse exit 2 |
| User reads priority as verdict | JSON has no verdict; note says pre-filter only |
| No writes/trace | no trace/model/sandbox |

## Agent notes

- The guardrail is structural: no `Assessment`, no `Verdict`, no `UnverifiedCause`, no `verdict` key.
- Do not add a `verdict: unverified` field "for consistency"; that would create a verdict.
- Do not tune the signal list on the corpus; it is a fixed heuristic.
- Do not change `check`/`bundle`/`verify`/`corpus` or A5.
- Commit per phase; full suite before each commit.

## Assumptions

- The static list is a queue heuristic, not a detection list; no accuracy claim.
- A low priority is not safe; a high priority is not malicious.
- A10 is optional and not the moat; the sandboxed run remains the verdict.
