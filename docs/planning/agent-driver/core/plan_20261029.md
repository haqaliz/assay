## 2. Implementation phases

### Phase 1 — Records and budget arithmetic

**Goal:** the data types, no I/O.
**Files:** `src/assay/agent/records.py`, `src/assay/agent/__init__.py`,
`tests/test_agent_records.py`.

**API (exact):**
```python
class RunCause(StrEnum):
    MISSING_KEY = "missing-key"; MODEL_FAILED = "model-failed"; COST_CAPPED = "cost-capped"
    STEP_LIMIT = "step-limit"; WALL_LIMIT = "wall-limit"; SANDBOX_UNAVAILABLE = "sandbox-unavailable"

@dataclass(frozen=True, slots=True)
class Usage:
    input_tokens: int = 0
    output_tokens: int = 0
    def __add__(self, other: "Usage") -> "Usage"
    # rejects negative ints / bools in __post_init__

@dataclass(frozen=True, slots=True)
class ModelPrice:
    input_per_mtok: float
    output_per_mtok: float
    def cost(self, usage: Usage) -> float   # usd

@dataclass(frozen=True, slots=True)
class Budget:
    max_usd: float
    max_steps: int = 20
    max_wall_seconds: float = 300.0
    # all positive; max_usd and max_wall_seconds are floats, not bools

@dataclass(frozen=True, slots=True)
class ToolCall:
    id: str; name: str; arguments: Mapping[str, object]

@dataclass(frozen=True, slots=True)
class ToolResult:
    ok: bool; output: str; record: RunRecord | None = None

@dataclass(frozen=True, slots=True)
class ToolAction:
    call: ToolCall; result: ToolResult

@dataclass(frozen=True, slots=True)
class RunOutcome:
    cause: RunCause | None
    final_text: str | None
    steps: int
    actions: tuple[ToolAction, ...]
    usage: Usage
    cost_usd: float
    @property
    def finished(self) -> bool      # cause is None and final_text is not None

class AgentError(RuntimeError): ...
class AgentUnavailable(AgentError):   # cause: RunCause
class ModelFailed(AgentError): ...    # converted to cause=MODEL_FAILED by drive()
```
**Tests first:** the arithmetic, validation, `finished`, closed `RunCause` set.
**Commit:** `feat(agent): run records, usage pricing and budget`

### Phase 2 — Toolbox

**Goal:** one sandbox run per model tool call, validated at the trust boundary.
**Files:** `src/assay/agent/tools.py`, `tests/test_agent_tools.py`, fixtures as needed.

**API:**
```python
MAX_TOOL_PAYLOAD_BYTES = 1_000_000
CURL = Path("/usr/bin/curl")

@dataclass(frozen=True, slots=True)
class ToolSpec:
    name: str; description: str; input_schema: Mapping[str, object]

TOOLS: tuple[ToolSpec, ...]        # read_file, write_file, run_shell, http_get

class Toolbox:
    def __init__(self, sandbox: Sandbox, run_root: Path) -> None
    def execute(self, call: ToolCall) -> ToolResult
```
**Rules:**
- `__init__`: `run_root` must exist, be a directory, not a symlink; `curl` must exist (else
  `AgentUnavailable("missing-tool")`).
- Required string args: `read_file.path`, `write_file.path` + `write_file.content`,
  `run_shell.command`, `http_get.url`. Empty or non-string → `ok=False`, no sandbox run.
- `write_file`: reject content whose UTF-8 length > cap; create `run_root/.assay-io` and write a
  temp payload there; argv `[/bin/cp, payload, path]`; delete the payload afterwards in a `finally`.
- `http_get`: `allow_network=(NetRule("*", 80), NetRule("*", 443))`; other tools `()`.
- Every call: `JailConfig(run_root=..., allow_network=..., env={}, keep=True)`; `Limits()` default
  is fine.
- Output: `record.stdout + record.stderr` when failed, capped to 1 MB; `ok = record.ok`.
- Exceptions from `Sandbox.run` (`SandboxFailed`, `SandboxUnavailable`) → return `ok=False` with the
  exception text and `record=None`; `SandboxUnavailable` from `__init__`-time checks still raises.
**Tests first (FakeSandbox):** argv and network per tool, `env == {}`, run_root identity, invalid
args, unknown tool, oversized payload, denial record preserved, payload cleaned up.
**Commit:** `feat(agent): sandboxed toolbox for model tool calls`

### Phase 3 — Deterministic task

**Goal:** one reproducible task per skill.
**Files:** `src/assay/agent/tasks.py`, `tests/test_agent_tasks.py`.
**API:** `task_for(skill: Skill) -> str`. Includes `skill.name` and `skill.description`, tells the
model to carry out the skill's stated purpose, choose a small example if input is needed, use the
tools, and finish with a short summary. Deterministic; no dates, ids or randomness.
**Commit:** `feat(agent): deterministic task for a skill`

### Phase 4 — Anthropic adapter

**Goal:** the real BYOK path, testable without sockets.
**Files:** `src/assay/agent/base.py` (protocol + `Message` + `ModelReply`),
`src/assay/agent/anthropic.py`, `tests/test_agent_anthropic.py`.

**API:**
```python
# base.py
class Model(Protocol):
    price: ModelPrice
    def complete(self, messages: Sequence[Message], tools: Sequence[ToolSpec]) -> ModelReply: ...

@dataclass(frozen=True, slots=True)
class Message:
    role: Literal["system", "user", "assistant", "tool"]
    content: str
    tool_call_id: str | None = None
    tool_calls: tuple[ToolCall, ...] = ()

@dataclass(frozen=True, slots=True)
class ModelReply:
    text: str | None
    tool_calls: tuple[ToolCall, ...]
    usage: Usage

# anthropic.py
Transport = Callable[[urllib.request.Request], bytes]

class AnthropicModel:
    def __init__(self, model: str, api_key: str, price: ModelPrice,
                 max_tokens: int = 1024, transport: Transport | None = None,
                 endpoint: str = "https://api.anthropic.com/v1/messages") -> None
    @classmethod
    def from_env(cls, model: str, price: ModelPrice, **kwargs) -> "AnthropicModel"
    def complete(self, messages, tools) -> ModelReply
```
**Mapping:** `system` message → top-level `system` string (required; `ValueError` if absent); other
messages → `messages` with `assistant` tool_use blocks and `tool` results grouped into a user
message with `tool_result` blocks; `tools` → `[{"name","description","input_schema"}]`.
Headers: `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`.
Response: `content` blocks `text` and `tool_use`; `usage.input_tokens` / `output_tokens`.
Any `urllib.error.HTTPError`, `URLError`, timeout, `json.JSONDecodeError`, or unexpected shape →
`ModelFailed`.
**Tests first:** env-missing refusal, request body/headers, response parsing, error mapping.
**Commit:** `feat(agent): Anthropic messages adapter with injected transport`

### Phase 5 — Driver

**Goal:** the bounded loop.
**Files:** `src/assay/agent/driver.py`, `src/assay/agent/__init__.py`,
`tests/test_agent_driver.py`.

**API:** `drive(skill: Skill, task: str, model: Model, toolbox: Toolbox, budget: Budget) -> RunOutcome`.

**Rules:**
- Start `messages = [Message("system", skill.body), Message("user", task)]`.
- Before each model call: `WALL_LIMIT` if elapsed > budget, `COST_CAPPED` if `spent >= max_usd`.
- `model.complete` raising `ModelFailed` → `cause=MODEL_FAILED`; any other `AgentError` propagates.
- After a reply: `spent += model.price.cost(reply.usage)`, `usage += reply.usage`; if
  `spent > max_usd` return `COST_CAPPED` immediately (do not execute that reply's tool calls).
- No tool calls → finished, `final_text = reply.text or ""`.
- Else append the assistant message, execute each call via `toolbox.execute`, append one `Message`
  per result (`role="tool"`, `tool_call_id`, content = output or a short failure text), collect
  `ToolAction`s.
- Loop exhausts → `STEP_LIMIT`. `steps` = model calls made.
**shortcut comment:** wall time is checked between calls; a single slow call is bounded by the
transport's 60 s timeout.
**Tests first:** 3-turn success, cost cap, step limit, wall limit, model failure, no key in any
captured config.
**Commit:** `feat(agent): bounded agent driver`

## 4. Testing strategy

- Fake `Sandbox` records `(argv, config)` and returns a canned `RunRecord`; no process is spawned.
  Real confinement is a separate `darwin` test.
- Fake `Model` replays a scripted list of `ModelReply`s and records the messages it saw; usage is
  fixed so cost arithmetic is exact.
- Anthropic tests inject `transport` and assert the serialized body; no sockets.
- Never assert wall-clock exact values; wall-limit test injects a monotonic clock.

## 5. Environment & secrets

No env vars needed for tests. The manual gate run needs `ANTHROPIC_API_KEY` (absent in this
environment) and a model id + price chosen by the user. Keys are read only by `from_env`, never
written, never passed into `JailConfig.env`.

## 6. Edge cases

| Condition | Result |
|---|---|
| Missing key | `AgentUnavailable(MISSING_KEY)` before any call |
| curl missing | `AgentUnavailable` at `Toolbox` construction |
| Tool args wrong type or empty | `ok=False`, no sandbox run, model sees the error |
| `write_file` content > 1 MB | `ok=False`, no write |
| Denied action | `ok=False`, `RunRecord.denials` preserved |
| `Sandbox.run` raises | `ok=False`, `record=None`, text explains |
| Model returns text and tool calls | execute the calls, keep the text in the transcript |
| Model returns empty text, no tools | finished with `final_text=""` |
| Cost crosses cap mid-reply | `COST_CAPPED`, that reply's tools not executed |
| Step cap reached | `STEP_LIMIT`, actions preserved |

## 7. Agent execution notes

- Human checkpoint after Phase 2: review the argv builders by eye (they are the trust boundary).
- Do not add retries, streaming, a second provider, or a pricing table.
- Do not let `drive()` catch `SandboxUnavailable`: the caller must see that Assay could not confine.
- Ask before changing the tool schemas (they define what A4 can observe).

## 8. Deviations during implementation (2026-10-29)

An adversarial review after the six phases found two host-boundary defects and several accounting
gaps. All are fixed and covered by failing tests first:

1. **A2 change (evidence integrity).** The child could truncate or forge `.assay/stdout|stderr`,
   which is where denials are classified from. The profile now denies `file-write*` on
   `<run_root>/.assay`, and a capture directory that cannot be created is `SandboxFailed`.
2. **Staging moved outside the run root.** A `run_shell` symlink of `.assay-io` could redirect a
   parent-side payload write onto the host. Payloads now live in a parent-owned temp dir that the
   jail may only read (`allow_read_extra`), and `Toolbox` is a context manager that removes it.
3. **`http_get` was dead in the real jail and argv-injectable.** It now requires `http`/`https`
   (no `file://`, no leading `-`), passes `--url`, resolves the host in the parent (`--resolve`)
   because the jail allows TCP but not DNS, and re-allows `/private/etc/ssl` for TLS. Verified by
   hand against `https://example.com` (200).
4. **Sandbox loss is named, not swallowed.** `SandboxUnavailable` propagates out of `Toolbox` and
   becomes `cause=SANDBOX_UNAVAILABLE` in `drive()`; `SandboxFailed` stays a failed action.
5. **Budget hardening.** Worst-case cost is estimated before each call; `max_actions` and
   `ACTION_LIMIT` bound a single reply with many tool calls; tool output sent back to the model is
   truncated to 16k chars; NaN/inf are rejected.
6. **Anthropic hardening.** Whitespace keys refused, `stop_reason=max_tokens|refusal` is
   `MODEL_FAILED`, `http.client.HTTPException` is mapped, and error bodies are kept.
7. **`task_for` no longer repeats the skill body** (it is the system prompt); `RunCause` gained
   `ACTION_LIMIT`.
