## Testing strategy

- Unit: pattern table (attack/clean), narrowed patterns, `REVIEW` cap.
- Integration: held-out report before/after; the main 20 pinned.
- Regression: the real control labels/no false MALICIOUS; the shell held-out unchanged.
- No model/network.

## Agent notes

- Measure the baseline **before** editing `INSTRUCTION_PATTERNS`.
- Do not make instruction findings `HIGH`/`MALICIOUS`; the cap is the guardrail.
- Do not tune the shell patterns or the 20-case corpus.
- The held-out set is a one-shot control; a future change needs a fresh set.
- Commit per phase; full suite before each commit.

## Assumptions

- The malicious bodies are safe synthetic text; no execution.
- The main corpus's instruction case still matches the existing patterns; the clean cases do not use
  the refined phrases.
- Strict `MALICIOUS` recall remains 0/4 by design; the gain is detection/clean review.
