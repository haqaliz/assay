Assay

Execution-grounded security verifier for AI agent skills.

Runs a skill in a macOS sandbox against a real agent, captures what it actually did, and checks that against what it claims to do. The verdict is backed by a record a third party can verify.

View on GitHub Install from PyPI Audit protocol

quickstart

$ uv tool install assayhq
$ assay triage path/to/SKILL.md
$ assay check path/to/SKILL.md --model ... --max-cost 0.01

A sandboxed run needs a provider, model and cost cap. The quickstart uses a pre-filter and the CLI only; see the README for a full run.

01 Why

The scan is not the verdict.

A static pattern or a model's opinion can flag a candidate. Assay's claim is narrower and stronger: what the skill actually did in a confined run, captured and checked against what it declared.

Execution decides

A sandboxed, observed run assigns the verdict. A high static score is a reason to run, never a result.

Honest verdicts

CLEAN means the run matched the declared scope, not that the skill is safe. UNVERIFIED is never a pass.

Evidence you can verify

Canonical traces and SSH-signed bundles. assay verify checks the signature, the hashes and the replay offline.

An audit gate

Private runs, a reviewer who did not run the target, a 30-day disclosure window and a correction route before publication.

02 How it works

One run, five links in the chain.

1

Ingest

Parse a Claude Code or OpenClaw SKILL.md, or a Cursor rule, into a typed record with its declared scope.

2

Run

Run it against a real agent in Seatbelt, with a scrubbed environment, confined writes and cost/step caps.

3

Capture

Record file, network, shell and instruction events as a canonical, content-addressed trace.

4

Assess

Diff observed against declared scope. Four classes, a severity floor that cannot be lowered, and a named cause when undecidable.

5

Attest

Sign the trace and its exact source into a bundle. Anyone can check the signature and replay the verdict offline.

MCP is a separate capability: assay mcp inspects startup and tools, and assay mcp-report runs a task and reports UNVERIFIED/FLAGGED. A manifest declares startup, not behavior, so there is no CLEAN or MALICIOUS server claim.

04 Status

Shipped, measured, and honest about the gaps.

v0.1.0 is on PyPI. The engine covers A1–A8 (file-based) and A10; MCP has a sandbox session, stdio client, inspector and conservative report. The 20-case benchmark, held-out shell/instruction sets and a private real-world control are in the repo.

The private own-skill audit dry run was reviewed privately on 2026-11-10: 21/21 bundles verified, 12/15 runs decided, no HIGH, no MALICIOUS. A public audit still needs an independent reviewer and the disclosure window. The reviewer call is issue #31.

Platforms. Sandboxed execution is macOS-only today. Linux and Windows via WSL2 are planned, not shipped; there is no unconfined fallback. The non-sandbox commands are not macOS-specific, but Linux CI is still part of the plan. Platform plan →

Assay is a verifier, not a guarantee. CLEAN is per-run and scope-matched; UNVERIFIED is never a pass.
